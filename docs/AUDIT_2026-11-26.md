## How fixes are kept from breaking the running system
- **Database:** files that have already run on your project are never edited. Each fix ships as a new `supabase/setup/update_after_<version>.sql` with these protections:
  - It runs in one transaction, so it applies fully or not at all.
  - It refuses to run twice.
  - It is additive only: new grants or replaced function bodies. It never deletes or rewrites your data.
- **Tests:** the 51 database tests now run with the same permissions as your live project (no automatic access), so a missing permission fails a test instead of the live app.
- **Frontend:** fixes stay local until you deploy, and every change passes the typecheck, lint, build and database tests first.
